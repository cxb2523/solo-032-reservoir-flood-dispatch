# 水库入库流量与泄洪调度台

汛期值班调度系统：入库过程线、库容曲线查表削峰、水位涨速提前预泄、逐档闸门调节、
下游安全流量顶托判定、按传播时间倒推的预警发布，以及双人值班台账冲突检测。

## 运行

机器要求：Python 3.14，**只用标准库**，无任何第三方依赖。

```bat
run.bat
:: 或
python tools\generate_data.py   :: 重新生成 data\reservoir.json（可选，文件已随仓库提供）
python server.py
```

服务监听 `0.0.0.0:8000`。若本机 `127.0.0.1:8000` 已被其他程序占用，
控制台会打印本机 LAN IP，用 `http://<LAN-IP>:8000` 访问即可。

## 数据（data/reservoir.json）

- 三座水库：青峰、碧龙、松鸣；每库 5 个闸门，开度 0–4 档，每档对应下泄流量。
- 库容曲线 0.5m 一档，档间线性插值；汛限水位与当前水位逐库登记。
- 下游 4 个村镇河段：安全流量 + 到村镇传播时间 + 沿程区间来水系数。
- 洪水过程线 36h、第 14h 洪峰（青峰 1800 m³/s，各库按尺度缩放），界面上有洪峰标注。
- 两处**故意保留的脏数据**（原文件不改，界面红条提示、计算前处置）：
  - 碧龙水库闸门编号 `G-03` 出现两次：保留两扇闸，用内部 uid `BLW-03 / BLW-04` 区分；
  - 松鸣水库库容曲线 85.0m 一档库容写反、破坏单调性：用相邻档插值修复后参与计算。

## 调度规则（硬约束）

1. 水位超过汛限即开闸，每小时表格与「调度依据」列表写明查表/涨速计算过程。
2. 下游河道流量 = 水库下泄 + 沿程区间来水，超过安全流量即削峰/错峰；
   水库超过汛限后错峰库容用尽，按保坝优先允许穿透约束，顶托时段在图与表中标红留痕。
3. 闸门一小时只能调一档（0→1→2…，禁止 0 直接拉到 4），枚举全部可行档位组合选最贴近目标且不顶托的一组。
4. 两个值班员共用乐观锁版本号：后提交者基于旧版本会收到 409 冲突提示，刷新后才能改，不能互相覆盖。

## 两套调度口径并排切换

- **A 库容查表削峰**：以汛限水位对应库容为目标逐时回算需泄流量。
- **B 涨速提前预泄**：按近 2h 水位涨速与来水涨幅预判，未到汛限先泄到汛限以下 1m 腾库。

切换时左侧水位过程线与右侧闸门开度表整体联动；各自给出最高水位、最大下泄、
下游超安全时段数与削掉的峰值（绝对值与削峰率）。

## 预警

发布时刻 = 首次超安全流量到达村镇时刻 − 传播时间。勾选「下游安全流量下调20%」后，
哪几段、哪些时段顶线以及预警该几点发，会自动在下游表中冒出来；
落在 23:00–06:00 的发布时刻带「深夜照发」标识，不做早晨顺延。

## 交付自检

界面右上「交付自检」按钮（或 `GET /api/selfcheck`）跑三件事：
青峰水库第 12 小时 水位→库容→下泄的链路核对并对照两套口径；
安全流量砍两成后的顶托时段与预警时刻；同一场降雨连算两遍的闸门/下泄/水位一致性。
